## Part 3 — Data-in-path story: "Day one: get my team's docs in. Day 30: are they stale?"

**Day one, as a new team member, using only the UI:**

1. You land on `/new` — "Drop something." Four radio choices: url / video / file / text. You pick "file," click **Choose File**, and the native picker is confirmed **single-file only** (`multiple: false`, `webkitdirectory: false`). To ingest a folder of 40 documents this way, you do it 40 times, one dialog each.
2. If you instead find **Stewdio** (`/stewdio`, only reachable via the top-nav "Stewdio" link, not obviously the "drop a folder" entry point a new user would guess) and notice the small 📎 icon beside the chat box, the underlying `<input type=file>` there genuinely does accept `multiple` and `.zip/.7z/.tar/.gz/...` — so *zip-your-folder-first-then-attach-via-chat* is a real bulk path. It exists, but it's not documented as the way in on `/new`, and nothing on `/new` points you to it. A new team member reading the README's "Drag in a PDF, Office doc, or zipped folder" line would reasonably expect that affordance on the obvious "New work item" page, not buried in a chat attach icon on a different page.
3. Either way, before you can create anything you must pick an **Intent** (hard-required, "friction is the discipline" per the tooltip). The eight intents that exist today are all scripture-study/demo-world-shaped (`book-study`, `demo-world`, `general-research`, `memory-tend`...) — there's no generic "ingest my team's docs" intent pre-built; you'd click "+ new" and write your own before your first document goes in.
4. Once ingested, your documents land in the same `Studies`/`Library` list as everything else — a list that is, today, **391 rows dominated by Star Trek/Cosmere/My Little Pony RPG-rulebook chunks** (roughly 300+ of the 391) with no visible per-project isolation in the browse view (the `Project` dropdown filters, but the default view mixes everything). Your team's docs will visually drown in unrelated test content unless you remember to filter by project every time.
5. Your documents' `project_association` may or may not get set correctly — six of the ten existing projects show "0 work items" in `/projects` despite having 95–289 pages of real, ingested content each. If this pattern repeats for your ingested folder, your own Projects page count will silently read "0" forever even though the content is there.

**Day 30 — are they stale?**

The honest answer today is: **probably, and you would not be told.**

- The mechanism that is supposed to keep things current — `/scheduled`'s cron pipelines (`book-digest-hourly`, `memory-tend-gentle` every 30 min, `demo-world-cron` every 3h, `ai-news-7am` daily, `science-news-weekly`) — **has been stalled for roughly two weeks** as of this walk, confirmed live in both `/scheduled` and the Dashboard's "Last 7 scheduled runs (14d ago)" panel. Nothing in the UI raises an alarm about this; every row reads "(due now)" in the same neutral gray/white styling whether it's 5 minutes overdue or 14 days overdue.
- `/watchman` (the drift-detection pass that flags when docs disagree with each other) is running and does log real "drift" counts — but there is **no drill-down** to see *which* docs drifted or why, so even when the system does notice staleness, a human can't inspect it from the UI.
- There is no documented (in `docs/`) or visible (in the UI) **re-ingest/re-sync** affordance for a previously-attached document or folder — if your team's source folder changes on day 20, nothing in `/new`, `/stewdio`, or the docs describes how to tell the substrate "re-read this." You would re-attach manually and hope the system de-dupes or supersedes correctly (untested in this walk — read-only constraint).
- `/trust` (the trust-ladder that's supposed to build confidence in autonomous runs over time) shows **zero scores** despite 673 real work items — a feature that exists in the data model but has never actually accumulated evidence, so there's no visible signal of "this pipeline has proven itself" vs. "this is unproven" to help you judge freshness/reliability of anything downstream.

Net: the UI **can** get a folder in (via zip + Stewdio chat, with real MIME support), but nothing about the day-one flow signals *that's* the way, nothing prevents the content from disappearing into an already-noisy shared list, and the automated freshness machinery that would keep it current has been silently dead for two weeks with no alert anywhere a new user would see it.
